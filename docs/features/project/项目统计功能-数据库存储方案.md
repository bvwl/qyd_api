# 项目统计功能 - 数据库存储方案

## 方案说明

采用**数据库存储 + Redis缓存**的混合方案：

- ✅ **数据库存储**：统计数据持久化存储，安全可靠
- ✅ **Redis缓存**：提升查询性能，减少数据库压力
- ✅ **定时同步**：每小时自动同步统计数据
- ✅ **手动同步**：支持手动同步历史数据

## 数据模型

### ProjectDailyStats（项目每日统计）

```python
class ProjectDailyStats(BaseModel):
    """项目每日统计"""
    date = fields.DateField(description="统计日期", index=True)
    update_count = fields.IntField(default=0, description="当天更新的账号数量")
    project = fields.ForeignKeyField("models.ProjectInfo", related_name="daily_stats")
    
    class Meta:
        table = "project_daily_stats"
        unique_together = [("project_id", "date")]  # 每个项目每天只有一条记录
```

### 数据库表结构

```sql
CREATE TABLE `project_daily_stats` (
    `id` CHAR(36) NOT NULL PRIMARY KEY,
    `date` DATE NOT NULL,
    `update_count` INT NOT NULL DEFAULT 0,
    `project_id` CHAR(36) NOT NULL,
    `create_time` DATETIME(6) NOT NULL,
    `update_time` DATETIME(6) NOT NULL,
    UNIQUE KEY (`project_id`, `date`),
    KEY (`date`),
    KEY (`project_id`, `date`),
    FOREIGN KEY (`project_id`) REFERENCES `project_info` (`id`) ON DELETE CASCADE
);
```

## 数据同步

### 自动同步（推荐）

在 `backend/app/main.py` 中添加定时任务：

```python
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from app.utils.stats_sync import scheduled_sync_stats

# 创建调度器
scheduler = AsyncIOScheduler()

# 每小时同步一次统计数据
scheduler.add_job(
    scheduled_sync_stats,
    'cron',
    minute=0,  # 每小时的第0分钟执行
    id='sync_stats'
)

# 启动调度器
scheduler.start()
```

### 手动同步

```python
from app.utils.stats_sync import sync_today_stats, sync_historical_stats

# 同步今天的数据
await sync_today_stats()

# 同步最近30天的数据
await sync_historical_stats(days=30)
```

from app.crud.project.stats import project_stats_crud

## API接口

### 1. 获取仪表盘统计数据

```bash
GET /v1/project/stats/dashboard?days=7
```

**数据流程**:
1. 检查Redis缓存
2. 如果缓存不存在，从数据库查询
3. 将结果写入Redis缓存（5分钟）
4. 返回结果

### 2. 获取项目今天的更新数量

```bash
GET /v1/project/stats/project/{project_id}/today
```

**数据流程**:
1. 从数据库查询今天的统计记录
2. 返回 `update_count` 字段

### 3. 同步统计数据（管理员）

```bash
POST /v1/project/stats/sync?days=30
```

手动触发同步最近N天的统计数据。

## 性能优化

### 1. 数据库索引

```sql
-- 复合索引（最常用）
KEY `idx_project_daily_stats_project_id_date` (`project_id`, `date`)

-- 单列索引
KEY `idx_project_daily_stats_date` (`date`)
KEY `idx_project_daily_stats_project_id` (`project_id`)
```

### 2. Redis缓存

- **时间序列数据**: 缓存5分钟
- **单日统计**: 缓存24小时
- **使用Redis DB 10**: 避免与其他功能冲突

### 3. 查询优化

```python
# ✅ 一次查询获取所有数据
stats_list = await db_read(ProjectDailyStats).filter(
    project_id__in=project_ids,
    date__gte=start_date,
    date__lte=end_date
).all()

# ❌ 避免N+1查询
for project_id in project_ids:
    stats = await db_read(ProjectDailyStats).filter(project_id=project_id).all()
```

## 数据一致性

### 问题：统计数据与实际不符

**原因**:
- 统计数据未及时同步
- 账号更新后统计未更新

**解决**:
```bash
# 重新同步今天的数据
python -c "
import asyncio
from app.utils.stats_sync import sync_today_stats
from tortoise import Tortoise
from app.core.settings import TORTOISE_ORM

async def main():
    await Tortoise.init(config=TORTOISE_ORM)
    await sync_today_stats()
    await Tortoise.close_connections()

asyncio.run(main())
"
```

### 问题：Redis缓存与数据库不一致

**解决**:
```bash
# 清除所有统计缓存
curl -X POST http://127.0.0.1:6080/v1/project/stats/cache/clear \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## 迁移和备份

### 数据库迁移

```bash
# 导出统计数据
mysqldump -u user -p database project_daily_stats > stats_backup.sql

# 导入到新数据库
mysql -u user -p new_database < stats_backup.sql
```

### Redis故障恢复

Redis只作为缓存，故障后：
1. 数据不会丢失（存储在数据库中）
2. 查询会直接访问数据库
3. Redis恢复后自动重建缓存

## 优势对比

### 数据库存储方案 vs 纯Redis方案

| 特性 | 数据库存储 | 纯Redis |
|------|-----------|---------|
| 数据安全 | ✅ 持久化存储 | ❌ 可能丢失 |
| 迁移友好 | ✅ 标准SQL导出 | ⚠️ 需要特殊工具 |
| 查询性能 | ⚠️ 较慢（有缓存） | ✅ 极快 |
| 数据一致性 | ✅ 强一致性 | ⚠️ 最终一致性 |
| 历史数据 | ✅ 长期保存 | ❌ 需要定期备份 |
| 运维成本 | ⚠️ 需要备份 | ⚠️ 需要持久化配置 |

## 总结

✅ **数据安全**: 统计数据持久化存储在数据库中  
✅ **性能优化**: Redis缓存提升查询速度  
✅ **易于维护**: 支持手动和自动同步  
✅ **迁移友好**: 标准SQL导出导入  
✅ **故障恢复**: Redis故障不影响数据完整性
