# 项目统计功能 - 仪表盘优化

## 需求说明

优化仪表盘的项目统计图表显示方式：

1. **默认显示总和曲线**：显示所有项目每天更新数量的总和（单根曲线）
2. **按需加载项目曲线**：用户可以通过下拉选择框选择要查看的项目，显示多根曲线

## 实现方案

### 1. 后端API修改

#### 1.1 修改仪表盘统计API

**文件**: `backend/app/apis/v1/project/stats.py`

**修改点**:
- 添加 `project_ids` 查询参数（可选，逗号分隔的项目ID列表）
- 不传 `project_ids` 时，返回所有项目的总和曲线
- 传入 `project_ids` 时，返回指定项目的各自曲线

**API接口**:
```
GET /v1/project/stats/dashboard?days=7
GET /v1/project/stats/dashboard?days=7&project_ids=xxx,yyy
```

**返回数据格式**:

总和曲线（不传project_ids）:
```json
{
  "code": 1,
  "message": "成功",
  "data": [
    {
      "project_id": "total",
      "project_name": "总计",
      "dates": ["2026-01-19", ..., "2026-01-25"],
      "counts": [10, 15, 20, 18, 25, 30, 28]
    }
  ]
}
```

项目曲线（传入project_ids）:
```json
{
  "code": 1,
  "message": "成功",
  "data": [
    {
      "project_id": "xxx",
```

### 2. CRUD层修改

**文件**: `backend/app/crud/project/stats.py`

**新增方法**: `get_total_stats_time_series()`

**功能**: 计算所有项目每天更新数量的总和

**实现逻辑**:
1. 获取所有项目的每日统计数据
2. 按日期汇总所有项目的数量
3. 返回单条总和数据

**代码示例**:
```python
async def get_total_stats_time_series(
    self,
    project_ids: List[str] | None = None,
    days: int = 7,
    use_cache: bool = True
) -> List[Dict]:
    # 获取每日统计数据
    daily_stats = await self.get_daily_update_counts(project_ids, days)
    
    # 生成日期列表
    dates = [...]
    
    # 计算每天的总和
    total_counts = []
    for date in dates:
        day_total = sum(
            project_stats.get(date, 0)
            for project_stats in daily_stats.values()
        )
        total_counts.append(day_total)
    
    # 返回总和数据
    return [{
        'project_id': 'total',
        'project_name': '总计',
        'dates': dates,
        'counts': total_counts
    }]
```

```typescript
export const getProjectStatsForDashboard = (params: { 
  days: number
  project_ids?: string  // 逗号分隔的项目ID列表
```

## 使用说明

### 1. 查看总和曲线

**操作**: 不选择任何项目（默认状态）

**效果**: 显示一根粗的蓝色曲线，表示所有项目每天更新数量的总和

**适用场景**: 快速了解整体更新趋势

### 2. 查看特定项目曲线

**操作**: 在项目选择框中选择一个或多个项目

**效果**: 显示选中项目的各自曲线，可以对比不同项目的更新趋势

**适用场景**: 
- 对比不同项目的活跃度
- 分析特定项目的更新规律
- 排查项目更新异常

### 3. 切换时间范围

**操作**: 选择「最近7天」「最近14天」「最近30天」「最近90天」

**效果**: 图表显示对应时间范围的数据

### 4. 刷新数据

**操作**: 点击「刷新」按钮

**效果**: 重新从服务器加载最新数据

### 5. 清除缓存（仅管理员）

**操作**: 点击「清除缓存」按钮

**效果**: 清除Redis缓存，下次查询将从数据库重新计算

## 权限控制

### ADMIN/GM（管理员）
- 默认显示：所有项目的总和
- 可选项目：所有项目
- 特殊权限：可以清除缓存

### IT/MANUAL（普通用户）
- 默认显示：自己项目的总和
- 可选项目：仅自己关联的项目
- 限制：无法查看其他用户的项目

## 性能优化

### 1. 缓存策略

**总和数据缓存**:
- 缓存键：`total_stats_{days}` 或 `total_stats_{project_ids}_{days}`
- 过期时间：5分钟
- 命中率：高（大部分用户查看总和）

**项目数据缓存**:
- 缓存键：基于项目ID列表和天数
- 过期时间：5分钟
- 命中率：中等（用户选择项目后）

### 2. 数据库优化

**读写分离**:
- 统计查询使用从库（`db_read()`）
- 轮询负载均衡，分散读压力
- 主库故障时自动降级

**查询优化**:
- 按日期范围过滤，减少数据量
- 使用索引（project_id, date）
- 预聚合数据，避免实时计算

## 总结

这次优化实现了更灵活的统计数据展示方式：

✅ **默认简洁**：显示总和曲线，快速了解整体趋势
✅ **按需详细**：选择项目后显示详细对比
✅ **权限控制**：用户只能查看自己的项目
✅ **性能优化**：缓存 + 读写分离
✅ **用户体验**：多选下拉框，操作便捷

用户可以根据需要在「总览」和「详细对比」之间灵活切换，既满足了快速查看的需求，又保留了深入分析的能力。
