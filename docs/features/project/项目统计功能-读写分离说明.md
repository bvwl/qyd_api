# 项目统计功能 - 读写分离说明

## 概述

项目统计功能现在**已支持读写分离**，提供更高的可用性和性能。

## 读写分离策略

### 读操作（使用从库）

所有查询操作都使用从库，减轻主库压力：

```python
# 1. 查询统计数据
stats_list = await db_read(ProjectDailyStats).filter(...).all()

# 2. 查询项目信息
projects = await db_read(ProjectInfo).filter(...).all()

# 3. 查询账号数据
accounts = await db_read(ProjectAccount).filter(...).all()

# 4. 获取单条记录
stats = await db_read(ProjectDailyStats).get_or_none(...)
```

### 写操作（使用主库）

所有创建、更新、删除操作都使用主库：

```python
# 1. 创建统计记录
await ProjectDailyStats.create(...)  # 默认使用主库

# 2. 更新统计记录
stats.update_count = count
await stats.save()  # 默认使用主库

# 3. 删除旧数据
await db_write(ProjectDailyStats).filter(...).delete()
```

## 高可用性优势

### 1. 主库故障时

如果主库出现故障：

- ✅ **读操作仍然可用**：从从库读取数据
- ✅ **查询统计数据**：仍然可以查看历史统计
- ✅ **查看图表**：前端图表仍然可以显示
- ❌ **写操作不可用**：无法创建/更新统计数据

**影响范围**：
- 定时同步任务会失败
- 手动同步会失败
- 但用户仍然可以查看历史数据

### 2. 从库故障时

如果从库出现故障：

- ✅ **写操作仍然可用**：可以创建/更新统计数据
- ❌ **读操作会失败**：查询会报错

**解决方案**：
- 系统会自动切换到主库读取（如果配置了故障转移）
- 或者返回缓存数据（如果Redis可用）

### 3. 主从延迟

主从复制可能有延迟（通常几秒到几分钟）：

**影响**：
- 刚写入的数据可能在从库查询不到
- 统计图表可能有几分钟的延迟

**缓解措施**：
- 统计数据本身就不要求实时性
- 有Redis缓存减少查询频率
- 定时任务每小时同步一次

## 代码实现

### CRUD层（`app/crud/project/stats.py`）

```python
from app.core.database import db_read, db_write

class ProjectStatsCRUD:
    
    async def get_daily_stats_from_db(self, ...):
        """查询统计数据（使用从库）"""
        query = db_read(ProjectDailyStats)  # 从库
        stats_list = await query.filter(...).all()
        return stats_list
    
    async def upsert_daily_stats(self, ...):
        """创建/更新统计数据（使用主库）"""
        # 读取时使用主库（确保数据一致性）
        stats = await ProjectDailyStats.get_or_none(...)
        
        if stats:
            # 更新（主库）
            stats.update_count = count
            await stats.save()
        else:
            # 创建（主库）
            await ProjectDailyStats.create(...)
```

### 同步工具（`app/utils/stats_sync.py`）

```python
from app.core.database import db_read, db_write

async def sync_today_stats():
    """同步今天的统计数据"""
    # 查询账号数据（使用从库）
    accounts = await db_read(ProjectAccount).filter(...).all()
    
    # 统计数量
    project_counts = {}
    for account in accounts:
        project_counts[account.project_id] += 1
    
    # 更新统计表（使用主库）
    for project_id, count in project_counts.items():
        await project_stats_crud.upsert_daily_stats(...)
```

## 配置说明

### 环境变量

在 `.env` 文件中配置读写分离：

```env
# 主库配置
DB_HOST=127.0.0.1
DB_PORT=3307
DB_USER=root
DB_PASSWORD=zhiyu666
DB_NAME=qyd

# 从库配置（可选）
DB_SLAVE1_HOST=127.0.0.1
DB_SLAVE1_PORT=3308

DB_SLAVE2_HOST=127.0.0.1
DB_SLAVE2_PORT=3309

# 启用读写分离
DB_READ_WRITE_SPLIT=1
```

### 不启用读写分离

如果不配置从库或设置 `DB_READ_WRITE_SPLIT=0`：

- `db_read()` 和 `db_write()` 都会使用主库
- 系统仍然正常工作
- 只是没有读写分离的优势

## 性能优势

### 1. 分散负载

- **主库**：只处理写操作（创建、更新、删除）
- **从库**：处理所有读操作（查询）
- **结果**：主库压力减小，整体性能提升

### 2. 查询性能

统计功能的查询操作：

- 查询统计数据：使用从库
- 查询项目信息：使用从库
- 查询账号数据：使用从库

**优势**：
- 从库可以专门优化查询性能
- 不影响主库的写入性能
- 可以添加更多从库横向扩展

### 3. 缓存配合

读写分离 + Redis缓存 = 最佳性能：

```
用户请求
  ↓
检查Redis缓存
  ↓ (未命中)
查询从库
  ↓
返回数据 + 写入缓存
```

## 故障处理

### 场景1：主库故障

**现象**：
- 写操作失败
- 定时同步失败
- 但查询仍然正常

**处理**：
1. 检查主库状态
2. 如果主库无法恢复，提升从库为主库
3. 更新配置文件
4. 重启服务

### 场景2：从库故障

**现象**：
- 查询失败
- 前端图表无法加载

**处理**：
1. 检查从库状态
2. 临时禁用读写分离：`DB_READ_WRITE_SPLIT=0`
3. 重启服务（所有查询会使用主库）
4. 修复从库后重新启用

### 场景3：主从延迟过大

**现象**：
- 刚写入的数据查询不到
- 统计数据不准确

**处理**：
1. 检查主从复制状态
2. 检查网络延迟
3. 检查从库负载
4. 临时使用主库查询（修改代码）

## 最佳实践

### 1. 写操作后的读取

如果需要立即读取刚写入的数据，使用主库：

```python
# 写入数据
await ProjectDailyStats.create(...)

# 立即读取（使用主库，避免主从延迟）
stats = await ProjectDailyStats.get_or_none(...)  # 默认使用主库
```

### 2. 批量操作

批量操作时，考虑使用事务：

```python
from tortoise.transactions import in_transaction

async with in_transaction():
    for project_id, count in project_counts.items():
        await project_stats_crud.upsert_daily_stats(...)
```

### 3. 缓存优先

优先使用缓存，减少数据库查询：

```python
# 1. 尝试从缓存获取
cached_data = await stats_cache.get_project_stats_time_series(...)
if cached_data:
    return cached_data

# 2. 缓存未命中，查询数据库（从库）
data = await project_stats_crud.get_project_stats_time_series(...)

# 3. 写入缓存
await stats_cache.set_project_stats_time_series(...)
```

## 总结

项目统计功能现在支持读写分离，提供：

✅ **高可用性**：主库故障时，读操作仍然可用  
✅ **高性能**：读写分离，分散负载  
✅ **可扩展性**：可以添加更多从库  
✅ **灵活性**：可以随时启用/禁用读写分离  

**关键点**：
- 读操作使用从库（`db_read()`）
- 写操作使用主库（默认或 `db_write()`）
- 配合Redis缓存，性能更佳
- 主库故障时，查询仍然可用
