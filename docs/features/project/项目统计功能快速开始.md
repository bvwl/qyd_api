# 项目统计功能 - 快速开始指南

## 功能概述

项目统计功能已完整实现，包括后端API、数据库存储、Redis缓存、定时同步和前端图表展示。

### 核心特性

✅ **数据库存储**: 使用 `project_daily_stats` 表持久化存储统计数据  
✅ **Redis缓存**: 使用Redis DB 10独立存储，提升查询性能  
✅ **定时同步**: 每60分钟自动同步统计数据  
✅ **权限控制**: ADMIN/GM看所有项目，IT/MANUAL看自己的项目  
✅ **前端图表**: 使用ECharts绘制曲线图，支持7/14/30/90天切换  
✅ **缓存管理**: 管理员可手动清除缓存和同步数据

## 快速启动

### 1. 后端配置

#### 1.1 环境变量配置

编辑 `backend/.env` 文件，确保以下配置正确：

```env
# Redis配置（统计缓存使用DB 10）
REDIS_HOST=127.0.0.1
REDIS_PORT=6378
REDIS_PASSWORD=redis_fNmAxZ
REDIS_DB=0

# 统计功能配置
ENABLE_STATS_SYNC=1                    # 启用统计同步
STATS_SYNC_INTERVAL_MINUTES=60         # 同步间隔（分钟）
```

#### 1.2 数据库初始化

运行迁移脚本创建统计表：

```bash
cd backend
python db/apply_project_daily_stats_migration.py
```

#### 1.3 初始化历史数据

初始化最近30天的统计数据：

```bash
cd backend
python init_project_stats.py
```

#### 1.4 启动后端服务

```bash
cd backend
python start.py
```

服务启动后，定时任务会自动运行，每60分钟同步一次统计数据。

## 功能使用

### 1. 查看统计图表

在仪表盘页面，可以看到"项目账号更新趋势"图表：

- **时间范围切换**: 支持7天、14天、30天、90天
- **刷新数据**: 点击"刷新"按钮重新加载数据
- **清除缓存**: 管理员可点击"清除缓存"按钮清除Redis缓存

### 2. 权限说明

#### 数据权限
- **ADMIN/GM**: 可以看到所有项目的统计数据
- **IT/MANUAL**: 只能看到分配给自己的项目的统计数据

#### 功能权限
- **清除缓存**: 仅ADMIN可见和使用
- **同步数据**: 仅ADMIN可通过API调用

### 3. API接口

#### 3.1 获取仪表盘统计数据

```bash
GET /v1/project/stats/dashboard?days=7
Authorization: Bearer {token}
```

响应示例：
```json
{
  "code": 1,
  "message": "成功",
  "data": [
    {
      "project_id": "xxx",
      "project_name": "项目A",
      "dates": ["2026-01-19", "2026-01-20", ..., "2026-01-25"],
      "counts": [10, 15, 20, 18, 25, 30, 28]
    }
  ]
}
```

#### 3.2 获取项目今天的更新数量

```bash
GET /v1/project/stats/project/{project_id}/today
Authorization: Bearer {token}
```

#### 3.3 清除统计缓存（仅管理员）

```bash
POST /v1/project/stats/cache/clear
Authorization: Bearer {token}

# 清除指定项目的缓存
POST /v1/project/stats/cache/clear?project_id={project_id}
```

#### 3.4 手动同步统计数据（仅管理员）

```bash
POST /v1/project/stats/sync?days=30
Authorization: Bearer {token}
```

## 技术架构

### 数据流程

```
1. 定时任务（每60分钟）
   ↓
2. 统计项目账号更新数量
   ↓
3. 存入数据库（project_daily_stats表）
   ↓
4. 更新Redis缓存（DB 10）
   ↓
5. 前端查询时优先从Redis读取
   ↓
6. Redis未命中时从数据库读取并缓存
```

### 数据库表结构

```sql
CREATE TABLE project_daily_stats (
    id CHAR(36) PRIMARY KEY,
    project_id CHAR(36) NOT NULL,
    stat_date DATE NOT NULL,
    update_count INT DEFAULT 0,
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_project_date (project_id, stat_date),
    INDEX idx_project_id (project_id),
    INDEX idx_stat_date (stat_date)
);
```

### Redis缓存结构

```
# 缓存Key格式
stats:project:{project_id}:date:{date}

# 缓存值
{update_count}

# 过期时间
7天（604800秒）
```

## 故障排查

### 问题1: 图表不显示数据

**可能原因**:
- 数据库表未创建
- 没有历史数据
- Redis连接失败

**解决方案**:
```bash
# 1. 检查数据库表
cd backend
python db/check_project_table.py

# 2. 初始化历史数据
python init_project_stats.py

# 3. 检查Redis连接
python -c "from app.utils.stats_cache import StatsCache; cache = StatsCache(); print('Redis连接成功')"
```

### 问题2: 定时任务不运行

**可能原因**:
- `ENABLE_STATS_SYNC` 未设置为1
- 后端服务未启动

**解决方案**:
```bash
# 1. 检查环境变量
cd backend
grep ENABLE_STATS_SYNC .env

# 2. 查看定时任务日志
tail -f logs/scheduler.log

# 3. 手动触发同步
curl -X POST "http://localhost:6080/v1/project/stats/sync?days=1" \
  -H "Authorization: Bearer {your_token}"
```

### 问题3: 权限错误

**可能原因**:
- Token过期
- 用户角色不正确

**解决方案**:
```bash
# 1. 重新登录获取新Token
# 2. 检查用户角色
curl "http://localhost:6080/v1/user/user/me" \
  -H "Authorization: Bearer {your_token}"
```

### 问题4: 前端图表不显示

**可能原因**:
- ECharts未安装
- 容器高度为0
- 数据格式错误

**解决方案**:
```bash
# 1. 检查ECharts是否安装
cd frontend
npm list echarts

# 2. 重新安装
npm install echarts

# 3. 查看浏览器控制台错误
```
