# 菜单显示问题修复总结

## 问题描述
1. 新增的邮件查看器页面无法在菜单中显示
2. 管理员应该能看到所有菜单，即使路由未在数据库中初始化

## 解决方案

### 1. 添加邮件查看器路由到数据库
**文件**: `backend/db/init_routes.py`

在邮箱管理菜单下添加了"邮件查看器"子菜单：
```python
{
    "name": "mail-viewer",
    "path": "/mail/viewer",
    "title": "邮件查看器",
    "component": "MailViewer",
    "sort": 2,
}
```

### 2. 管理员默认显示所有菜单
**文件**: `frontend/src/components/Layout/index.tsx`

#### 修改内容：
1. **添加默认菜单配置**
   - 定义了完整的菜单结构 `DEFAULT_MENU_ITEMS`
   - 包含所有功能模块（用户、项目、服务器、邮箱、API文档）
   - 包含新增的"邮件查看器"菜单项

2. **修改菜单加载逻辑**
   ```typescript
   // 如果用户是管理员，直接使用默认菜单
   if (userInfo?.roles?.some((role: any) => role === 'ADMIN' || role.code === 'ADMIN')) {
     setMenuItems(DEFAULT_MENU_ITEMS)
     return
   }
   
   // 非管理员使用从后端获取的路由权限
   const items = buildMenuItems(routes)
   setMenuItems(items)
   ```

3. **错误处理优化**
   - 管理员加载失败时，使用默认菜单
   - 非管理员加载失败时，只显示仪表盘

## 注意事项

1. **前端菜单 ≠ 后端权限**
   - 前端菜单只控制显示
   - 后端API仍然有权限验证
   - 管理员看到菜单不代表绕过权限

2. **路由同步**
   - 新增功能时需要同时更新：
     - `backend/db/init_routes.py` - 数据库路由
     - `frontend/src/components/Layout/index.tsx` - 默认菜单
     - `frontend/src/router/index.tsx` - 前端路由

3. **角色判断**
   - 代码中判断管理员：`role === 'ADMIN' || role.code === 'ADMIN'`
   - 兼容字符串和对象两种格式
