# 读写分离 - 轮询负载均衡 + 健康检查

## 概述

已将读写分离的负载均衡策略从**随机选择**升级为**轮询（Round Robin）+ 缓存的健康检查**。

## 新特性

### 1. 轮询负载均衡

使用轮询算法在多个从库之间均匀分配请求：

```python
# 第1次查询 -> slave1
# 第2次查询 -> slave2
# 第3次查询 -> slave1
# 第4次查询 -> slave2
# ...
```

**优势**：
- ✅ 完全均匀分配
- ✅ 可预测的负载分布
- ✅ 无状态，简单高效

### 2. 健康检查（带缓存）

每30秒检查一次从库健康状态，避免每次请求都检查：

```python
# 健康检查缓存
_slave_health_cache = {
    'slave1': {
        'is_healthy': True,
        'check_time': 1706169600
    },
    'slave2': {
        'is_healthy': True,
        'check_time': 1706169600
    }
}
```

**优势**：
- ✅ 自动检测从库故障
- ✅ 缓存结果，不影响性能
- ✅ 故障时自动降级到主库

### 3. 自动降级

如果所有从库都不健康，自动降级到主库：

```python
⚠️  所有从库都不健康，降级到主库读取
```

## 实现细节

### 核心代码（`backend/app/core/settings.py`）

```python
# 轮询索引（全局变量）
_read_db_index = 0

# 从库健康状态缓存
_slave_health_cache: Dict[str, Dict] = {}
_health_check_interval = 30  # 健康检查间隔（秒）


def check_slave_health(slave_name: str) -> bool:
    """
    检查从库健康状态（带缓存）
    
    :param slave_name: 从库名称
    :return: True表示健康，False表示不健康
    """
    global _slave_health_cache
    
    current_time = time.time()
    
    # 检查缓存
    if slave_name in _slave_health_cache:
        cache_entry = _slave_health_cache[slave_name]
        # 如果缓存未过期，直接返回缓存结果
        if current_time - cache_entry['check_time'] < _health_check_interval:
            return cache_entry['is_healthy']
    
    # 执行健康检查
    is_healthy = True
    try:
        from tortoise import Tortoise
        
        # 尝试获取连接
        conn = Tortoise.get_connection(slave_name)
        if conn:
            is_healthy = True
        else:
            is_healthy = False
    except Exception as e:
        is_healthy = False
        print(f"⚠️  从库 {slave_name} 健康检查失败: {e}")
    
    # 更新缓存
    _slave_health_cache[slave_name] = {
        'is_healthy': is_healthy,
        'check_time': current_time
    }
    
    return is_healthy


def get_read_db():
    """
    获取读数据库连接名称（轮询负载均衡 + 健康检查）
    
    策略：
    1. 使用轮询（Round Robin）在多个从库之间分配请求
    2. 健康检查带缓存（每30秒检查一次），避免性能影响
    3. 如果所有从库都不健康，降级到主库
    """
    global _read_db_index
    
    if not DB_READ_WRITE_SPLIT:
        return "default"
    
    # 可用的从库列表
    slaves = ["slave1", "slave2"]
    
    # 尝试最多2次（遍历所有从库）
    for _ in range(len(slaves)):
        # 轮询选择从库
        slave = slaves[_read_db_index % len(slaves)]
        _read_db_index += 1
        
        # 健康检查（带缓存）
        if check_slave_health(slave):
            return slave
    
    # 所有从库都不健康，降级到主库
    print("⚠️  所有从库都不健康，降级到主库读取")
    return "default"
```

## 性能分析

### 健康检查开销

**第1次查询**（缓存未命中）：
- 轮询选择：O(1)
- 健康检查：~1-5ms（获取连接）
- 总开销：~1-5ms

**后续查询**（缓存命中，30秒内）：
- 轮询选择：O(1)
- 健康检查：O(1)（直接返回缓存）
- 总开销：<0.1ms

**结论**：
- ✅ 性能影响极小
- ✅ 30秒内的查询几乎无开销
- ✅ 比随机选择更可靠

### 对比

| 策略 | 负载均衡 | 故障检测 | 性能开销 |
|------|---------|---------|---------|
| 随机选择 | ✅ 长期均衡 | ❌ 无 | 极低 |
| 轮询 | ✅ 完全均衡 | ❌ 无 | 极低 |
| **轮询+健康检查** | ✅ 完全均衡 | ✅ 自动检测 | **极低** |

## 使用场景

### 场景1：正常运行

```
请求1 -> 轮询 -> slave1 -> 健康检查（缓存命中）-> slave1
请求2 -> 轮询 -> slave2 -> 健康检查（缓存命中）-> slave2
请求3 -> 轮询 -> slave1 -> 健康检查（缓存命中）-> slave1
请求4 -> 轮询 -> slave2 -> 健康检查（缓存命中）-> slave2
```

### 场景2：slave2故障

```
请求1 -> 轮询 -> slave1 -> 健康检查（健康）-> slave1
请求2 -> 轮询 -> slave2 -> 健康检查（不健康）-> 尝试slave1 -> slave1
请求3 -> 轮询 -> slave1 -> 健康检查（健康）-> slave1
请求4 -> 轮询 -> slave2 -> 健康检查（缓存：不健康）-> 尝试slave1 -> slave1
```

### 场景3：所有从库故障

```
请求1 -> 轮询 -> slave1 -> 健康检查（不健康）-> 尝试slave2 -> 健康检查（不健康）-> 降级到主库
请求2 -> 轮询 -> slave2 -> 健康检查（缓存：不健康）-> 尝试slave1 -> 健康检查（缓存：不健康）-> 降级到主库
```

### 场景4：从库恢复

```
# 30秒后，缓存过期
请求N -> 轮询 -> slave2 -> 健康检查（重新检查）-> 健康 -> slave2

# 或者手动清除缓存
POST /v1/system/database/health/clear-cache
请求N+1 -> 轮询 -> slave2 -> 健康检查（重新检查）-> 健康 -> slave2
```

## 故障处理

### 从库故障

**现象**：
- 日志中出现健康检查失败的警告
- 请求自动路由到健康的从库或主库

**处理**：
1. 检查从库状态
2. 修复从库
3. 清除健康检查缓存（可选）

```bash
curl -X POST "http://localhost:6080/v1/system/database/health/clear-cache" \
  -H "Authorization: Bearer {admin_token}"
```

### 所有从库故障

**现象**：
- 日志中出现"降级到主库读取"的警告
- 所有读请求使用主库

**处理**：
1. 检查所有从库状态
2. 修复至少一个从库
3. 清除健康检查缓存
